# TT-35: Local Governed Council Runner v0.1

This creates a **real local Ollama deliberation path** through ThinkTank's existing LIVE runner, deterministic Crane Fly scheduling, Challenger, governance, Reality Gate, event kernel and replayable Decision Dossier. It is **a terminal command, not an HTTP API**. The user's own terminal command with an exact-file SHA approval is the execution boundary.

## Setup

Install Ollama, download at least one local model, then start the existing ThinkTank provider bridge in a separate terminal:

```sh
npm install
npm run bridge
```

The bridge listens on `127.0.0.1:3691` by default. This local mode deliberately **never** runs OpenAI or Kimi seats, even if API keys are configured elsewhere in your .env.

Build the standalone local council CLI:

```sh
npm run council:build
```

Either create the JSON contract with the matching Vessie #80 **Local Governed Council Contract** panel or edit a fresh copy of `tests/fixtures/local-council.sample.json`. Mode is council (5 turns), trio (3), or audit (2). Provide a real installed Ollama model name. The strict parser requires all authority and remote-provider fields **false**.

Read the contract without starting a provider:

```sh
npm run council:inspect -- /absolute/path/thinktank-local-council.json
```

The CLI reports the source-file SHA-256, planned role count/model and that approval is outstanding. **Read the file itself before proceeding.** SHA-256 here binds your terminal approval to the file's exact bytes; it does not authenticate the author or establish factual evidence.

Only after confirming the exact digest and agreeing to spend local compute:

```sh
npm run council:run -- /absolute/path/thinktank-local-council.json --approve-sha256=THE_64_CHARACTER_FILE_SHA256 --confirm-local-model-inference
```

The executable refuses missing/incorrect approval flags, disallowed fields, external model destinations, unsupported models, abnormal HTTP health, or a nonmatching local model reported by `GET /providers/status`. It uses *only* loopback `POST /providers/invoke` with `seatId:local`, the exact approved model, and roles generated by the real LIVE runner. Paid OpenAI/Kimi seats are explicitly disabled by **canonical operator events** before ThinkTank starts routing. No password/token is copied into Vessie.

## Output

The CLI writes to ignored `local-council-artifacts/`, with private-ish filesystem permissions, a timestamp/random basename, and no overwrite:

- `*-ledger.json` containing original executed provider turns, canonical event ledger, replay verification and explicit zero-authority flags.
- `*-decision-dossier.json` only if ThinkTank actually reaches synthesis and produces a decision. It matches **TEAR / EXPORT DOSSIER** shape, including the real decision basis, executionSource, model provider-turn references and unverified provenance attachment lists. It imports to the existing Vessie #77 ThinkTank Decision Bridge.

The CLI will return a nonzero exit status on incomplete or aborted sessions. It does not silently call this success. A real provider return often results in a **WITHHELD** dossier because no independently reviewed claims/excerpts were added; this is the expected conservative governance outcome, not evidence that the models malfunctioned.

## Limits and security

- This is not an authenticated council HTTP service, not Vessie's ability to remote-execute models, and not a production deployment claim. A later web API needs independent loopback authorization and secure origin handling; do not simply expose `/providers/invoke` to the internet.
- Actual Ollama inference can consume substantial **local compute/time**. Only the **maximum role-turn count** and wall-clock abort attempt are bounded here. `PROVIDER_MAX_OUTPUT_TOKENS` on the existing bridge determines the per-call output-token generation cap; this CLI does **not** override or prove that setting. Check its value before execution. Deadline aborting HTTP locally may not immediately stop generation already happening inside Ollama.
- This release intentionally contains **no automatic remote-provider fallback**, no pricing, no concurrent jobs and no autonomous action executor. The terminal remains responsible for approving each run.
- The environment and local provider bridge must be trusted by the operator. A service impersonating `127.0.0.1:3691` can make the observational preflight false. This is not service identity attestation.
- Ledger replay reconstructs canonical local state. It does not authenticate providers or establish that AI-generated statements are correct.
- The CLI writes provider text to local artifacts; review content for secrets/private data before copying or sharing. Files are not encrypted.
- The export includes no verified Ed25519 seals, witness signatures or third-party release publications. It does not confer Vessie Company approval, Anti-M evidence review, physical-world execution, or independently verified DONE.

## Verification

CI executes `npm test`, `npm run bridge:check`, `npm run bridge:test`, `npm run council:build`, a **read-only contract inspection**, and a real invocation of the bundled terminal `run` command against a **synthetic localhost mock bridge**. The mock accepts five role turns, and the test verifies generated ledger replay and WITHHELD dossier. An invalid SHA approval must refuse without a single provider request. Unit tests additionally exercise local-only Crane Fly role selection, provider-scope refusal, source:provider Challenger turns, replay exactness, withheld governance and cancellation.

**No real installed user Ollama model was run by CI**. An operator-run live session must be verified separately from its actual receipts.
